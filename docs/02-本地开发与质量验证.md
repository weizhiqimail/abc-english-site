# 本地开发与质量验证

## 1. 环境要求

- Node.js `^20.19.0` 或 `>=22.12.0`（与当前 Vite 7 的 `engines` 约束一致）。
- 已执行 `npm install`。
- 已通过 `npx vercel link` 关联正确的 Vercel 项目。
- Vercel development 环境中包含 `POSTGRES_PRISMA_URL` 和 `DATABASE_URL_UNPOOLED`。

项目通过 `vercel env run` 在进程内注入开发环境变量，不要求把生产凭据提交到仓库。

## 2. 常用命令

| 命令                   | 用途                          | 是否访问数据库             |
| ---------------------- | ----------------------------- | -------------------------- |
| `npm run dev`          | 同时启动 API 与 Vite 前端     | 是                         |
| `npm run server`       | 生成 Prisma Client 后启动 API | 是                         |
| `npm run server:dev`   | 以 nodemon 启动 API           | 是                         |
| `npm run web:build`    | 构建前端到 `server/dist`      | 否                         |
| `npm run vercel:build` | 生成 Prisma Client 并构建前端 | 仅读取环境配置，不执行迁移 |
| `npm test`             | 运行 Node 单元测试            | 当前测试不访问数据库       |
| `npm run test:smoke`   | 测试一个已经启动的 API        | 是，会创建并清理临时数据   |
| `npm run format`       | 用 Prettier 写入统一格式      | 否                         |
| `npm run format:check` | 只检查格式                    | 否                         |

`test:smoke` 默认访问 `http://127.0.0.1:3211`，可用 `SITE_TEST_URL` 指向其他测试环境。不要对生产环境随意执行会创建数据的冒烟测试。

## 3. 推荐验证顺序

```bash
npm test
npm run format:check
npm run web:build
```

涉及 API、认证或数据库查询时，再启动本地服务执行：

```bash
npm run dev
npm run test:smoke
```

## 4. 测试职责

- `server/src/tests/`：不依赖远程服务的快速单元测试。
- `server/src/scripts/smokeTest.js`：验证路由、认证、收藏和基础管理流程。
- 前端异步页面应覆盖快速切换路由、请求失败、取消请求和空查询等场景。
- 数据库性能结论必须基于代表性数据和查询计划，不能仅依据代码形态。

## 5. 代码注释原则

注释应说明约束和原因，例如 Vercel 多实例限制、复合查询键、请求取消的竞态原因。不要逐行复述代码。跨模块契约应同时记录在本目录文档中，避免只有某个实现文件知道规则。
