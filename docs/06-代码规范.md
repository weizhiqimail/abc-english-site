# 代码规范

本文档约束 `web/`、`server/`、`api/` 和 `prisma/` 中的新代码及重构代码。

## 1. 条件判断

三元表达式最多只能有一层，只用于简单二选一。禁止在条件、真值或假值分支中嵌套三元表达式。三个及以上分支应使用带注释的 `if / else if / else`、提前返回或具名函数。

```js
// 5xx 是服务端故障，其他已知请求失败按警告记录。
const logLevel = statusCode >= 500 ? "error" : "warning";

let installLabel = "查看安装方式";
// 已安装状态优先；只有未安装且浏览器支持时才能立即安装。
if (installed) {
  installLabel = "已安装";
} else if (installable) {
  installLabel = "立即安装";
}
```

所有 `if`、`else if` 和 `else` 都必须使用花括号，包括提前返回和只有一行的分支。禁止 `if (condition) return;`。

每组业务判断都应说明为什么需要判断或各分支的业务含义，不能只把代码翻译成中文。

## 2. 命名与状态类型

- 搜索文本使用 `queryStr`、`searchText` 或 `keyword`，不使用含义不明的 `query`。
- 错误字符串使用 `errorMsg`；异常对象使用 `error` 或 `requestError`。
- 布尔值使用 `is`、`has`、`can`、`should` 等前缀。
- 集合使用复数名称；函数使用动词开头，如 `queryUsers`、`createCollection`、`resolveStatusCode`。
- 状态名称必须和初始值类型匹配，禁止在同一状态中混用字符串、对象和布尔值。

```js
const [errorMsg, setErrorMsg] = useState("");
const [requestError, setRequestError] = useState(null);
```

## 3. 防御性数据访问

远端响应、路由参数、Local Storage 和用户输入都属于不可信边界。调用数组方法或读取多层字段前必须验证结构。

```js
const levels = Array.isArray(overview?.levels) ? overview.levels : [];

const identity = page.identity;
const subcategory = page.subcategory;
if (!identity || !subcategory) {
  return <div className="error-state">分类数据结构不完整</div>;
}
```

同一个深层字段使用多次时，应先提取为局部变量并集中判空。不能只用可选链掩盖必需字段缺失；页面继续运行所必需的字段应显示明确错误状态。

## 4. 前端 HTTP 请求

React 组件和 feature 文件禁止直接调用 `fetch`、`axios`、基础 `get/post/patch/remove`，也禁止拼接 API URL。

```text
web/src/https/index.js              Axios 实例、拦截器、超时、Cookie、错误和 Loading
web/src/https/requests/*.js         按业务域定义具名请求函数和 URL
web/src/features/**/*.jsx           只调用具名业务请求函数
```

请求参数通过 Axios `params` 传递。动态路径段必须编码或经过服务端允许值校验。页面卸载或条件变化时应使用 `AbortController` 取消旧请求，并忽略 `AbortError`。

```js
useEffect(() => {
  const controller = new AbortController();
  queryCategoryDetail(recordId, { signal: controller.signal })
    .then(setPage)
    .catch(handleRequestError);
  return () => controller.abort();
}, [recordId]);
```

## 5. 注释与文档

功能块、导出函数、复杂方法、重要参数、状态变量和非显然局部变量应有说明。注释重点解释：

- 判断、默认值或限制存在的原因；
- 输入、输出和副作用；
- 安全、权限、并发及数据一致性约束；
- 无法从类型和命名直接看出的业务规则。

不要逐行复述代码。复杂算法和跨模块契约还应同步更新 `docs/`。

测试中的断言必须通过测试名称、分组注释或断言消息说明契约。自定义 `assert` 必须提供失败消息。

## 6. 正则与魔法值

正则表达式必须先定义为具名常量，并说明允许或拒绝的内容，然后才能使用。

```js
// REQUEST_ID_PATTERN 只允许安全的短 ASCII 标识，避免控制字符污染日志。
const REQUEST_ID_PATTERN = /^[A-Za-z0-9._:-]{1,128}$/;
```

状态码、长度、分页和批处理大小等重复出现或具有业务含义的数字也应定义为具名常量。

## 7. Prisma 模型

每个 Prisma model 必须使用 `///` 说明表的业务用途。每个字段应说明含义、单位、是否可空和特殊格式；关系字段必须说明关系方向、外键及删除行为。

```prisma
/// 用户收藏夹；一名用户可拥有多个收藏夹。
model Collection {
  /// 收藏夹主键。
  id     Int  @id @default(autoincrement())
  /// 所属用户外键。
  userId Int  @map("user_id")
  /// 收藏夹到用户的多对一关系；用户删除时级联删除。
  user   User @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

修改字段或关系时，必须同步更新说明、SQL 迁移和数据库文档。注释不是迁移的替代品。

## 8. 提交前检查

```bash
npm test
npm run format:check
npm run web:build
```

人工审查还应确认：组件没有直接 URL、没有嵌套三元、没有无花括号 `if`、数组方法前完成结构校验、正则均已命名、Prisma 新字段带有说明。
