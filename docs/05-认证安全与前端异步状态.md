# 认证安全与前端异步状态

## 1. 认证流程

登录成功后，服务端生成随机令牌，浏览器只接收 `HttpOnly` Cookie；数据库保存 SHA-256 摘要。Cookie 使用 `SameSite=Lax`，生产环境启用 `Secure`。`optionalAuth` 为每个请求解析用户，受保护路由再使用 `requireAuth` 或 `requireAdmin`。

React 的 `AuthContext` 通过 `/api/auth/me` 获取公开用户。正常未登录响应是 `user: null`；网络失败和服务端 500 属于“身份状态无法确认”。上下文通过 `authError` 单独表达失败，受保护页面不会误跳登录页，并提供 `refreshAuth` 重试入口。

## 2. 修改请求安全

所有 POST、PUT、PATCH、DELETE 请求先经过 `sameOriginMutations`。有 `Origin` 时必须与代理后的 Host 一致。该检查与 `SameSite=Lax` 共同降低 CSRF 风险，但无 Origin 请求当前仍会放行，因此不能把它描述成完整 CSRF 方案。

Vercel 位于反向代理之后，代码会读取 `x-forwarded-host`。只有在部署平台会规范化代理头的前提下才能信任该值；本地代理也必须保留真实 Origin/Host 关系。

## 3. 前端请求状态约定

依赖路由参数或查询参数的请求必须处理四种状态：

- `loading`：新参数开始加载时不显示旧参数的数据。
- `data`：只允许当前请求写入。
- `error`：开始新请求时清空，失败时显示可理解信息。
- `empty`：与 loading 和 error 区分。

项目使用原生 `AbortController` 取消过期请求。`web/src/services/api.js` 的 `get(path, options)` 会透传 `signal`。组件 cleanup 必须调用 `abort()`，并忽略 `AbortError`；否则快速切换搜索词或分类时，旧响应可能覆盖新页面。

## 4. 收藏局部状态

词汇卡片只有在收藏 API 成功后才调用 `onFavoriteChange`，所以当前实现不是乐观更新，请求失败不需要回滚。收藏状态使用 `(recordId, wordKey)` 复合身份。`favoriteOverrides` 只用于避免成功后立即重新加载整个收藏夹；切换用户或分类时必须清空，之后重新以服务端数据为准。收藏接口失败通过独立错误状态和重试入口展示，不能伪装成空收藏。

## 5. 日志与敏感信息

结构化日志会按字段名隐藏 password、token、cookie、authorization 和 API key，但普通错误字符串中的敏感值无法靠字段名识别。抛出错误时不要把 Cookie、连接串、完整请求 URL 或请求体拼进 message。持久化错误只能由管理员访问，并应制定保留周期。
